## What you get

<CardGrid>
	<Card title="Typed keys" icon="puzzle">
		A `Key[T]` names a service and fixes its type. `Register` takes a `T` and `Get` returns one: no
		`interface{}`, no type assertions.
	</Card>
	<Card title="Checked when you build" icon="approve-check">
		A value of the wrong type under a key doesn't compile. A concrete type goes in under an interface key as
		it is.
	</Card>
	<Card title="Reads never wait" icon="rocket">
		`Get`, `MustGet` and `Has` take no lock and allocate nothing, so goroutines reading at once don't slow
		each other down.
	</Card>
	<Card title="No globals" icon="close">
		The zero `Container` is ready to use, and nothing runs in `init()`. Declare a container where you wire
		your services.
	</Card>
	<Card title="Easy to fake" icon="random">
		A key works with any container. A test registers a fake under the same key in a container of its own.
	</Card>
	<Card title="Small API" icon="list-format">
		One type to hold services, one to name them, five methods. No dependencies beyond the standard library.
	</Card>
</CardGrid>

## Faster reads, with no reflection

<div class="landing-lead">
	v2 reads from a map it never changes once published, so a read is an atomic load and a lookup, with no lock.
	The calls that replace v1's reflection-based Invoke are about twenty times faster. Writes copy the map, so they
	cost more than v1's.
</div>

## Coming from v1

<div class="landing-lead">
	String ids become typed keys, and Invoke gives way to Get and MustGet, which return the type you want.
	The global container is gone: you declare your own.
</div>

<div class="compare">

```go title="v1"
gocontainer.Register("db", openDB())

gocontainer.MustInvoke("db",
	func(db *sql.DB) {
		// use db
	},
)
```

```go title="v2"
var DB = gocontainer.NewKey[*sql.DB]("db")

var c gocontainer.Container
DB.Register(&c, openDB())

db := DB.MustGet(&c) // use db
```
